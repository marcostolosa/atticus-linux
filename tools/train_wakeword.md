# Training the "Siri" wake-word model (livekit-wakeword)

Atticus's always-on wake word uses a small trained ONNX model
([livekit-wakeword](https://github.com/livekit/livekit-wakeword)). Detection
runs locally on CPU here; **training needs a CUDA GPU** (your RTX 3060 12 GB is
plenty - the model is tiny) and a **free LiveKit Cloud account** (speech for
training is generated by LiveKit's TTS, remotely; nothing paid).

Do the training **on the GPU PC**, then copy the resulting `.onnx` here.

---

## 1. One-time setup (GPU PC)

```bash
# uv (if you don't have it): https://docs.astral.sh/uv/
curl -LsSf https://astral.sh/uv/install.sh | sh

# Install the trainer (pulls torch/CUDA automatically)
uv tool install --python 3.13 "livekit-wakeword[train]"

# Free LiveKit Cloud account for the training TTS (one-time)
lk cloud auth          # opens a browser; create a free project
lk app env -w          # writes LIVEKIT_URL / API_KEY / API_SECRET to .env.local
set -a && source .env.local && set +a
```

First run downloads ~37 MB encoders + ~4 GB of noise/room/speech sources (cached
in `~/.cache/livekit-wakeword/`). Run every command below from one empty folder.

---

## 2. Train (GPU PC)

We optimize for a **Brazilian-Portuguese speaker** saying "Siri". Two good
options - train both and keep whichever tests best with your voice:

### Option A - "siri" (short, convenient)
```bash
livekit-wakeword setup --wakeword "siri" --language pt \
  --hard-negative "série" --hard-negative "siri" --hard-negative "ciranda" \
  --hard-negative "saída" --hard-negative "cedo" --hard-negative "siriema" --eval
livekit-wakeword train --wakeword "siri" --out ./models
livekit-wakeword eval  --wakeword "siri" --model ./models/siri.onnx
```
- `--language pt` makes the training voices pronounce it the Brazilian way
  ("SÍ-RI"), matching how you say it. (For an English pronunciation instead, drop
  `--language pt`.)
- If `setup` says "siri" is missing from the dictionary, add a pronunciation:
  `--pronounce "siri=S IH1 R IY0"` (English) - not needed with `--language pt`.
- `--hard-negative` lists pt-BR words that sound close, so the model learns to
  **ignore** them (fewer false triggers in normal speech). Add any that trip it.

### Option B - "ei siri" (recommended: longer = far fewer false positives)
```bash
livekit-wakeword setup --wakeword "ei siri" --language pt \
  --hard-negative "série" --hard-negative "ei" --hard-negative "aí" --eval
livekit-wakeword train --wakeword "ei siri" --out ./models   # -> ei_siri.onnx
livekit-wakeword eval  --wakeword "ei siri" --model ./models/ei_siri.onnx
```

`eval` prints recall at 0.5 false-alarms/hour. Higher is better (~0.9 is great).

### Test with YOUR voice before trusting it
```bash
uv tool install "livekit-wakeword[listener]"
livekit-wakeword listen ./models/siri.onnx --threshold 0.5
# say it 10x, and talk normally for a minute; adjust --threshold up if it
# false-fires, down if it misses. Note the value you like.
```

Tuning levers if it's not perfect: more `--hard-negative` phrases (re-run
`setup` + `train`), raise/lower the threshold, or try Option B.

---

## 3. Install the model here (this Omarchy machine)

Copy the chosen `.onnx` into the repo's `models/` as `<wakeword>.onnx`:

```bash
# from the GPU PC, e.g. via scp:
scp ./models/siri.onnx   user@YOUR-OMARCHY-PC:~/atticus-linux/models/siri.onnx
# (for "ei siri" the file is ei_siri.onnx; set wakeWord to "ei siri" below)
```

Then point Atticus at it in `~/.config/atticus/settings.json`:
```json
{ "wake": true, "wakeWord": "siri", "wakeThreshold": 0.5 }
```
(If you used "ei siri", set `"wakeWord": "ei siri"` - the shell looks for
`models/ei_siri.onnx`. You can also set `"wakeModel"` to an absolute path.)

Restart Atticus:
```bash
pkill -f 'python -m atticus_shell'; setsid -f ~/.local/bin/atticus
```
On start it prints `wake word on (livekit, trained model): say 'siri'`. Done -
say "Siri" and the box opens listening.

## Notes
- Until a model is present, Atticus falls back to a no-training Whisper spotter
  (works, but higher latency/CPU). The trained model is the "perfect" path.
- License: the livekit-wakeword code is Apache-2.0; the license of a **trained
  model file** (it bakes in LiveKit's encoders + TTS-generated speech) isn't
  spelled out, so **don't commit `models/*.onnx` to the public repo** (they're
  gitignored). Each user trains their own, or we revisit redistribution later.
